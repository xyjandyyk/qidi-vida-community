# 诊断反馈与私密日志

## 第一阶段：GitHub 即可运行

公开 Issues 收集版本、设备环境、操作时间、复现步骤和人工检查后的错误摘要。完整诊断文件不放公开仓库或公开 Issue 附件。

如维护者需要用 GitHub 管理内部分析，可另建私有仓库 `qidi-vida-diagnostics`，仅授权维护者访问，存放整理后的问题记录。它不是匿名上传服务；没有权限的群友不能直接向该私有仓库提交反馈。

## 第二阶段：App 内一键私密反馈

需要另外部署 HTTPS 接收服务和私密存储。用户选择日志并确认后上传，返回随机反馈编号；用户不需要 GitHub 账号。服务器整理脱敏摘要并关联 Issue，GitHub 写入凭据仅由服务器持有。

接收服务至少实现：上传大小限制、速率限制、短期上传授权、内容校验、日志保留期限、删除机制及维护者访问控制。不要将一个具有仓库写权限的固定令牌写入 APK。

这部分目前尚未部署；没有真实可用入口前，App 不显示“上传成功”或不可用的反馈按钮。
